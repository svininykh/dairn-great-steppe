# Как написать главу DAIRN

SPDX-License-Identifier: Apache-2.0

Глава — Markdown-файл в UTF-8: сведения о главе, затем одна или несколько
сцен. Сцена — фрагмент истории с текстом и возможными переходами.
Этот документ задаёт правила записи для `story-version: 0.2`;
экспериментальные возможности отмечены отдельно.

## Пример минимальной полной главы

Сохраните как `chapters/chapter-01.ru.md` и добавьте файл в
[список глав истории](DAIRN_STORY_FORMAT.md#манифест-истории).

```md
---
chapter-id: chapter-01
story-version: 0.2
language: ru
start: beginning
title: Начало пути
---

# Начало {#beginning}

:::scene
mood: calm
time: day
:::

Айбике выходит в степь.

:::choice
id: continue
goto: ridge
:::
Продолжить путь
:::

# У гряды {#ridge}

:::scene
mood: mystery
time: evening
:::

За грядой виден незнакомый след.
```

Это пример, не часть канона. Последняя сцена не содержит перехода;
автоматическое завершение главы форматом пока не определено.

## Сведения о главе

В начале файла между строками `---` укажите все пять полей:

| Поле | Что записать |
| --- | --- |
| `chapter-id` | ID главы, совпадающий с её `id` в `story.yaml`. |
| `story-version` | `0.2` — версия формата, не редакция текста. |
| `language` | Язык текста: например, `ru`, `kk` или `en`. |
| `start` | ID начальной сцены этой главы. |
| `title` | Название главы на языке текста. |

Значений по умолчанию и дополнительных стандартных полей нет.
ID глав, сцен и выборов стабильны и сохраняются при переводе;
названия, описания и реплики переводятся.

## Сцена

Начните сцену заголовком `# Название {#scene-id}`, затем добавьте
`:::scene`. ID сцены должен быть уникален в этой главе.
Всё до следующего заголовка сцены или конца файла относится к ней.
Между специальными блоками пишите обычный Markdown.

Порядок прохождения задают `start` и переходы, а не расположение сцен
в файле. Удобный порядок внутри сцены: метаданные → описание →
реплики → события и эффекты → выбор или проверка. Это рекомендация,
а не обязательный порядок выполнения.

## Как записывать блоки

Блок начинается строкой `:::имя`, далее идут поля `ключ: значение`.
У `scene`, `check`, `memory`, `effect` строка `:::` закрывает блок.
У `dialogue`, `choice`, `ai_insert` она отделяет поля от текста,
а следующая `:::` закрывает блок. Порядок полей свободный.

Ниже перечислены поддерживаемые поля. Необязательные отмечены явно.
Вложенные блоки и способ записать отдельную строку `:::` внутри текста
пока не определены — это открытый вопрос.

## `:::scene`

Настроение и время действия. Оба текстовых поля обязательны;
закрытого списка значений и игровых модификаторов нет.

```md
:::scene
mood: calm
time: day
:::
```

## `:::dialogue`

Реплика. Обязательны `speaker` — ID персонажа, не отображаемое имя —
и текст. Здесь и далее `guide` — условный персонаж автора.

```md
:::dialogue
speaker: guide
:::
Держись рядом.
:::
```

## `:::choice`

Выбор игрока. Обязательны стабильный `id`, `goto` — ID сцены этой главы —
и непустой текст выбора.

```md
:::choice
id: continue
goto: ridge
:::
Продолжить путь
:::
```

Необязательные поля: `icon` — подсказка для отображения,
`condition` — условие доступности, **экспериментально**.
Наблюдаемый пример: `condition: flag:trail-found`.
Операторы, составные условия и обработка отсутствующих флагов пока
не определены. Движок должен сообщить о неподдерживаемом условии,
а не считать его выполненным.

## `:::check`

Проверка с двумя исходами. Все четыре поля обязательны:
`stat` — имя характеристики, `difficulty` — числовая сложность,
`success` и `failure` — ID существующих сцен этой главы.

```md
:::check
stat: dexterity
difficulty: 8
success: safe-path
failure: difficult-path
:::
```

Это пример записи, не рекомендация по сложности. Алгоритм броска задают
игровые правила; поддерживаемые имена характеристик и параметры — движок.
Соответствие `dexterity` полю `initial-state.abilities.dex` здесь не задано.

## `:::memory`

Ссылка на событие. Обязательный `event` должен существовать в
`memory/events.yaml`, указанном в `book.yaml` → `memory-events`.
Запись события в журнал и повторное посещение обрабатывает движок.

```md
:::memory
event: trail-discovered
:::
```

## `:::ai_insert` — экспериментально

Место для реплики ИИ. В используемой форме обязательны все поля и текст:

```md
:::ai_insert
id: guide-warning
type: dialogue
character: guide
optional: true
max-chars: 160
:::
За грядой начинается незнакомая земля.
:::
```

`id` — стабильный ID вставки, `type: dialogue` — реплика,
`character` — ID персонажа, `optional: true` — генерация необязательна,
`max-chars` — положительный целый предел длины.
Другие типы, пропуск полей и способ подсчёта символов пока не определены.
Движок должен описывать, когда используется авторский текст вместо генерации.
Вставка соблюдает канон и ограничения ИИ книги, не меняет переходы и состояние истории.

## `:::effect` — экспериментально

Предполагаемое изменение состояния: `set-flag` задаёт имя флага,
`set-variable` — запись `имя=значение`. В наблюдаемых блоках есть
хотя бы одна из этих операций.

```md
:::effect
set-flag: trail-found
set-variable: route=detour
:::
```

Грамматика, типы значений, повторные операции и порядок применения
ещё не утверждены. Повторы `set-variable` в пилоте описаны в
[сопоставлении](PILOT-COMPARISON.md#главы-переходы-и-завершение);
это не разрешение повторять ключи YAML в манифестах.
Эффекты выполняет движок; исходные файлы книги не меняются.

## Переходы и завершение

Только `choice.goto`, `check.success` и `check.failure` задают переходы;
остальные блоки их не содержат. Все цели и начальный `start` должны
указывать на существующие сцены текущей главы. ID другой главы, путь
к файлу или специальный маркер конца недопустимы.

Конец сцены в тексте не означает переход к следующей сцене.
**Открытый вопрос:** как завершать главу и переходить к следующей.
Этим должен управлять уровень истории и движок; запись в `story.yaml`
или отдельная директива ещё не выбраны. Отсутствие переходов и эффекты
`chapter-01-complete` / `next-episode=...` не являются командами завершения.

## Проверка автором

Проверьте пять полей главы, совпадение ID и пути с `story.yaml`,
уникальность ID сцен, наличие начальной сцены, целей переходов и событий.
Экспериментальные блоки используйте только при документированной поддержке
движка. Локальный `validate_characters.py` главы не проверяет.
