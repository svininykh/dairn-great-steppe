# Сопоставление формата с пилотом

Отчёт наблюдений; не устанавливает правила формата.
Источники нормативных контрактов перечислены в [README](README.md).

Этот отчёт фиксирует наблюдаемое сопоставление перенесённых документов с
распакованным пилотом
[`books/battles-of-the-great-steppe-pilot/`](../books/battles-of-the-great-steppe-pilot/).
В задаче #24 отчёт актуализирован для расширения первоначального состояния.

## Пакет книги DAIRN

| Наблюдаемое правило | Статус | Подтверждение в пилоте |
| --- | --- | --- |
| `.dairn` является ZIP-контейнером без оборачивающего каталога книги | СООТВЕТСТВИЕ | Исходный пакет открывается как ZIP; `book.yaml` и `dairn-package.yaml` находятся в корне. |
| Манифест пакета имеет формат `dairn-book-package`, версию `0.1` и точку входа `book.yaml` | СООТВЕТСТВИЕ | `dairn-package.yaml`. |
| `book.yaml` задаёт начальную историю, а манифест истории — начальную главу и источники глав | СООТВЕТСТВИЕ | `book.yaml` → `first-trial`; `stories/first-trial/story.yaml` → `chapter-01`; все три исходных файла глав существуют. |
| Структурированные герои имеют стабильные уникальные ID | СООТВЕТСТВИЕ | `aibike`, `karashash`, `yersin` в `book.yaml`; дубликатов нет. |
| Первоначальное состояние принадлежит персонажу и допускает пропуски | СООТВЕТСТВИЕ | Частичные состояния `aibike`, `karashash`, `yersin`; проверяются локальными тестами формата. |
| Безопасность путей ZIP, реакция программы чтения на неизвестную версию и неизменность пакета во время игры | НЕ ПРОВЕРЯЕТСЯ | Пилот — статический артефакт; реализации программы чтения и состояния игровой сессии здесь отсутствуют. |
| Проверка дубликатов ID сцен и отсутствующих целей `goto` | НЕ ПРОВЕРЯЕТСЯ | Документ требует поведения валидатора; в этом репозитории валидатор не переносился. |
| Профиль потребителя первой главы | НЕ ПРОВЕРЯЕТСЯ | Маршрут к `chapter-01.ru.md` наблюдаем, но поведение потребителя не представлено. |

## Формат истории DAIRN

| Наблюдаемое правило | Статус | Подтверждение в пилоте |
| --- | --- | --- |
| `book.yaml`, `story.yaml` и Markdown глав описывают пилот | СООТВЕТСТВИЕ | Файлы присутствуют по путям, названным в документе. |
| Пилот использует `story-version: 0.2`, начальные блоки метаданных глав и директивы с разделителями `:::` | СООТВЕТСТВИЕ | Все три `chapter-*.ru.md` имеют начальные блоки метаданных; директивы присутствуют. |
| Технические ID не локализуются | СООТВЕТСТВИЕ | `story-id`, `chapter-id`, ID сцен и выборов имеют стабильные латинские значения при русскоязычном тексте. |
| Сцены, `scene`, `dialogue`, `choice`, `check`, `effect`, `memory` и `ai_insert` наблюдаются | СООТВЕТСТВИЕ | Они присутствуют в Markdown глав; `scene` использует `mood` и `time`, а `effect` — `set-flag`/`set-variable`. |
| Историческая модель одного `story.<language>.md` версии 0.1 | РАСХОЖДЕНИЕ | Пилот имеет многоглавную структуру и `story-version: 0.2`; перенесённый документ уже фиксирует это расхождение. |
| Многоязычные файлы повествования и документированный выбор запасного языка | НЕ ПРОВЕРЯЕТСЯ | В пилоте есть только `*.ru.md`; правило выбора запасного языка и другие локализации отсутствуют. |
| Полная грамматика `condition` / `effect` и смысл правил | НЕ ПРОВЕРЯЕТСЯ | Документ и `chapter-01.notes.md` оставляют эти вопросы открытыми; движок не переносился. |

## Персонажи пилота

Айбике и Қарашаш имеют собственные комплекты лука с колчаном и верховых
коней; неигровой персонаж Ерсін — плеть и наблюдаемые предметы с портрета. Характеристики
оружия взяты из раздела «Рынок», неизвестные значения пропущены. Принадлежность
сапсана не утверждена. Эти факты не являются универсальными требованиями
к персонажу. Основания перечислены в
[README пилота](../books/battles-of-the-great-steppe-pilot/README.md) и
[источниках первоначального состояния](../books/battles-of-the-great-steppe-pilot/initial-state-sources.ru.md).
Локализованные поля персонажей пилота представлены на `kk`, `ru`, `en`;
формат допускает и частичные переводы.

## Главы, переходы и завершение

Все три `chapter-*.ru.md` используют пять полей начального блока метаданных, заголовки
`# … {#scene-id}` и метаданные `mood` / `time`. Цели `choice.goto` и
`check.success` / `check.failure` локальны. Проверка в первой главе записана
как `stat: dexterity`, `difficulty: 8`; это не определение механики броска.
Вставки `ai_insert` содержат `id`, `type: dialogue`, `character`,
`optional: true`, `max-chars` и авторский текст.

Маршрут профиля потребителя первой главы: `first-trial` → `chapter-01` →
`stories/first-trial/chapters/chapter-01.ru.md`.
Конечная сцена первой главы `beyond-auls` содержит `chapter-01-complete`
и `next-episode=corsac-chase-part-2`; второй — `chapter-02-complete`
и `next-episode=icy-wings`. Это имена эффектов в тексте, не прямые ссылки
на ID глав `chapter-02` / `chapter-03`. В конце второй главы две строки
`set-variable` находятся в одном блоке. Их обработка как обычного YAML
словаря может потерять операцию. Точная грамматика остаётся экспериментальной.

Конечные сцены не содержат исходящих `choice` / `check`. `story.yaml`
перечисляет три главы, но не задаёт правила перехода между ними.
Реализация движка здесь отсутствует: автоматическое завершение и открытие
следующей главы по этим эффектам **НЕ ПРОВЕРЯЕТСЯ**. В
[формате главы](DAIRN_CHAPTER_FORMAT.md) завершение оставлено открытым вопросом.

## Вывод

Расхождение с исторической однофайловой моделью зафиксировано, но не
исправлялось. Задача #24 добавляет общий контракт первоначального состояния
героев и неигровых персонажей без изменения синтаксиса глав или устройства ZIP-контейнера.
Задача #31 разделяет нормативные контракты и наблюдения, не изменяя пилот.
